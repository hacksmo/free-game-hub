# Free Game Hub (CARCADE)

Android 车机 / 手机横屏游戏中心：打开即玩，全部游戏支持手柄，全面中文化，离线可玩。

## 当前版本 V1.23

- **大厅 60fps（第二轮）：不再逐帧重绘卡片**：真车报告拿到 `GPU: Adreno 643`（真显卡、硬件光栅），而画质已经在最低档 2 却仍不足 60fps —— 说明「再减特效」这条路到头了。真正的原因是**没建合成层的那几张卡每帧都在重绘**：一张卡是 720×1080 的封面按 413×620 显示，位置和缩放每帧都变，就必须按新尺寸重新采样整张图；一次拖拽 = 6 张卡 × 60 次/秒。现在位移改 `translate3d`（只搬已有纹理，不重绘像素），并把**视野内的卡全部提升为合成层**；软件光栅设备仍收敛到 ±1.5 张（那里每层都要 CPU 抠图）。GPU 类别在启动时由 `WEBGL_debug_renderer_info` 判定，写进 `html[data-gpu]`
- **帧采样真的能出数据了**：上一版采样门槛是「不足 12 帧直接丢弃」，而车上往往只滑一两下 —— 真车报告里就出现了「采样窗口 0 / 尚未采样」，等于把唯一证据关掉了。现在 ≥4 帧就给数据，报告新增**按 p50 折算的实际 fps**、掉帧帧数、累计采样帧数、**最差窗口**（主观感受到的是最差那一下）
- **PCM 中转不再卡顿（两处数量级问题）**：① 旧实现每个 AudioWorklet 量化块（128 采样）就过一次 JS 桥，48kHz 下**每秒 375 次**跨语言调用，全落在网页主线程上，把 rAF 切成碎片；现在在音频线程累积到 2048 帧再发，过桥降到 1/16（门禁实测平均 2048 采样/块）。② 旧实现把 48k 降成 24k 播，且是**裸抽取**（每两点取一点、无低通），高频折叠成毛刺，听感就是「有点卡」；现在 **AudioTrack 直接建在网页 context 的采样率上**（通常 48000），完全不转换，只有建轨失败才退回 24k 并带低通兜底
- **音频写入线程提到 `URGENT_AUDIO`**：默认优先级下，滑大厅/加载封面时写入线程被抢占 → 缓冲欠载 → 断续。同时缓冲加到 4 倍最小缓冲、预缓冲 200ms，报告新增 `underruns` / `latencyMs`
- **移除「网页音频走媒体通道」开关**：真车实测**怎么调都没有声音，且不是 bug** —— 它最终仍由 WebView 进程输出，而车机丢的正是这条流（`contentType=TYPE_0`）。车机浏览器播视频有声音是因为走 `MediaPlayer` 而非 WebView。保留只会让人反复试错
- **大厅滑动掉帧：不再靠调参数，改为「在设备上实测帧间隔，自动降档」**：开发机上无论怎么压都测不出车机的卡顿（软件光栅 + CPU 降速 20 倍仍是满帧、最差单帧 16.8ms），说明差的是**那块 SoC 每帧能吃下多少像素**，而不是 JS 算力。本版在大厅滑动时实测真实帧间隔，p90 超出 16.7ms 预算就自动降一档画质，直到帧间隔落进预算内。三档只减特效、不改布局与交互：**0 完整**（3D 透视 + 卡片阴影）→ **1 精简**（阴影收窄一半、去掉全屏背景模糊、遮罩不做补间）→ **2 平面**（去 3D 透视、去全部阴影、横幅背景退化为纯色）。单次抖动不会误降，连续两个窗口超预算才降一档；连续三个窗口宽裕才升回去
- **逐帧样式污染被清理（这是车机掉帧的直接来源）**：失效追踪实测——改造前一次拖拽产生 **1061 次「inline style 被改写」+ 367 次动画失效**，几乎每帧都在重绘；根因是逐帧对每张卡写 `--cf-shade` 自定义属性，逼着卡片遮罩层每帧重绘并每帧重启它的 opacity 过渡，另有逐帧写 `zIndex` / `pointerEvents`。现改为：遮罩按 0.25 档量化（跨过整卡才写一次）、`zIndex` 与 `pointerEvents` 只在真正变化时写，并对每张卡缓存上一帧的值跳过无变化写入。同条件复测降到 **498 次 / 343 次**，每帧内联样式写入从 6.24 次降到 2.23 次（−64%）
- **合成层只给视野内的卡**：拖拽期间原本给所有卡片都声明 `will-change`（12 个合成层），现只给 ±2 张视野内的卡建层，远处卡片不占纹理与合成带宽
- **切卡不再压出长帧**：背景横幅原本要等切卡那一刻才解码并做全屏模糊栅格化，车机上就是「滑完卡一下」。现在提前解码相邻两款的横幅，缓存里常驻解码结果
- **诊断报告新增「网页侧渲染结论」**：新增 GPU 渲染器字符串（`SwiftShader` / `llvmpipe` 出现即说明车机 WebView 在走软件光栅，这是决定对策的唯一分水岭）、实测滑动帧间隔 p50/p90/max 与掉帧数、当前画质档位。**滑动一次大厅再复制报告**，就能直接看出掉帧卡在哪一档
- **竞品/同类做法**（本轮调研）：Google TV 开源主屏 Free My TV 在 98 寸 TCL 上做到满帧，核心手法与本版一致——分层重绘（静止时零重绘）、模糊降维（小图模糊再放大）、阴影预缓存（九宫格贴图而非实时 box-shadow）、**给低端设备加 lite 档关掉阴影与过渡（实测 25fps → 60fps）**；Android TV 的 Leanback 横向列表靠视图回收，只保留屏上 3–5 个 item

- **「星际猎手」改为 16:9 全屏（原来是 3:4 竖条）**：这款打飞机游戏原本是竖版 480×800，在车机 1920×984 上只占中间一条窄带、两侧全黑。现改为**按屏幕实际比例铺满整屏**：逻辑高度固定 640（与原版横屏时完全一致，精灵物理尺寸与纵向手感不变），逻辑宽度按屏宽比例拉宽，缩放后正好铺满、左右不留黑边。车机 1920×984 / 1280×720 / 1024×600 三档实测均铺满无黑边
- **横向手感同步补偿（改宽度就得改速度）**：屏幕宽了 2.6 倍，若移动速度不变，横穿全屏要慢 2.6 倍，手感会明显变迟钝。玩家横向移动、鼠标跟随、触摸拖动，以及**敌方**的横向速度与敌弹横向分量，全部按宽度等比补偿 —— 宽屏下的躲避难度与竖版一致
- **敌人密度补偿**：宽屏场地面积大了 2.6 倍，敌人数不变就会显得空、难度变低。每波敌人数按宽度成比例增加（第 1 关由 5 架变 12 架横贯全屏），屏幕上的敌人密度与原版一致；V 字阵型的间距也同步缩放，宽屏上不再挤在中间一小条
- **网页音频 PCM 中转不再卡顿（采样率对齐）**：真车反馈「有声音但特别卡顿」，根因是**采样率不匹配**——网页 AudioContext 是 48000Hz、原生播放端是 24000Hz，速率对不上就变调 + 断续。本版把 AudioContext 的实际采样率随 PCM 一起传给原生，由原生做线性插值重采样（48k→24k，不在 JS 线程里做，弱车机友好）；播放前先攒够 150ms 再开播，避免 AudioTrack 一开始就欠载
- **「网页音频走媒体通道」开关真正生效**：此前 MediaStreamDestination 建在一个**独立的探测 context** 里，游戏自己的 context 根本没接进去，那个开关等于没开过。现改为在**每个游戏 context 内部**建 destination 并覆写该 context 的 `destination` —— 网页音频由此走 Chromium 的媒体元素管线（与浏览器播视频同一条路，正是真机确认放行的路径）；开关对已有页面立即生效，不必重启应用
- **启动白屏闪烁消除**：WebView 默认背景为白，页面加载完成前会先闪一下白屏再进 Logo 页；现将 WebView 背景设为与应用主题一致的深色
- **大厅滑动性能优化（合成层 10 → 1）**：实测 1920×984 @1.5x、CPU 降速 4 倍下 **60fps 满帧、零掉帧、零长任务**。原 10 张卡全部声明 `will-change`（= 10 个合成层），现只给中心卡与滑动中的卡留层；倒影的 `blur(1px)` + `mask-image` 渐变遮罩每帧都要重新光栅化，性能模式改为「无模糊 + CSS 渐变盖底边」的廉价做法，保留湿地面的质感
- **诊断新增 WebView 图形能力与屏幕刷新率**：若车机 WebView 实际走软件渲染（SwiftShader），则**换任何前端框架都救不了大厅卡顿**，只能改用原生 View / SurfaceView —— 这份数据能一锤定音，避免盲目重构
- **内置模拟器（放自己的经典游戏进去）**：游戏厅新增「模拟器」卡片，内置 EmulatorJS 4.2.3 运行时与 NES / Game Boy / GBA 三个核心（FCEUmm、Gambatte、mGBA）。**应用不含任何第三方游戏内容** —— 你把自己拥有的 ROM 放进 `rom/` 目录，或在后台直接投放，服务端托管后车机大厅随即出现该卡片，**手柄 / 触摸 / 键盘**全支持。核心（wasm）按需加载，不进每个游戏包
- **模拟器 ROM 投放（后台）**：管理后台新增「投放模拟器 ROM」区 —— 选一个 `.nes` / `.gb` / `.gba` 文件即可自动打包托管；服务端同时托管一份模拟器宿主（`/retro/`），让跨域 iframe 里的远程 ROM 也能加载到宿主与核心
- **APK 瘦身 12.8MB**：内置游戏的 zip 离线包与游戏本体是同一份内容的重复。Android WebView 不支持 Service Worker，`/__offline/<id>/` 由原生直接从 assets 供给，所以内置游戏**无需下载** —— 客户端在原生环境直接标为「已安装」，省一次下载也让 APK 不用重复打包
- **网页音频 PCM 中转（车机无声的正解）**：真车对照显示——**车机浏览器播放视频有声音、别的客户端也有声音，只有本应用无声**，而原生 AudioTrack 在 legacy stream type 1–20 上逐路都能听到。说明车机音频系统本身正常，被丢弃的是 **Chromium WebView 那条音频流**（诊断报告里它的 contentType 是 `TYPE_0` 未声明，而浏览器走 MediaPlayer 会声明 MOVIE/MUSIC）。本版不再赌路由，改为**绕过它**：网页里用 ScriptProcessor 采出渲染后的 PCM → 经 JS 桥交给原生 → 用**真车已验证 1–20 全部可闻**的 legacy AudioTrack 播放。设置页新增「网页音频 PCM 中转」开关（可运行时切换，不用重装）
- **修掉诊断的空测试音（此前判定无效）**：A/B 对照用的 WAV 采样数据长度为 0（44 字节只有头没有采样），A 组「HTMLMediaElement 测试音」**从来没真正发出过声音** —— 报告里 `duration=0`、`advanced=false` 是必然结果，那次结论不成立。现改为现场合成 0.5s/1kHz 真实音频，复测 `duration=0.5`、`advanced=true`
- **修掉「网页音频走媒体通道」开关（等于没开过）**：实现里 `new AudioContext({sinkId: mediaDest})` 传的是节点对象，而 `sinkId` 要的是**输出设备 id 字符串**，Chromium 抛异常后静默回落成普通 AudioContext —— 所以「试过没用」并不能证伪该假说
- **诊断补上音频流路由设备**：每条活跃播放流现在都带 `deviceId` / `deviceName`（`getAudioDeviceId` 从 API 26 就有，这车是 API 32，此前一直没采集），直接看出网页音频流被路由到哪个设备，不再靠猜
- **音频 shim 抽成独立资源文件**：`public/shim/audio-shim.js` 是唯一来源，真机与自动化探针跑同一份代码，杜绝「改了副本、探针还在测旧副本」的漂移
- **应用自动更新（SP4）**：设置页新增「应用更新」区——车机上不再需要手动拷贝安装包。启动时静默检查线上版本，有新版本就显示版本号与更新说明，点「下载并安装」即可覆盖安装（保留已有数据与已装游戏）。下载完成后**必须校验 sha256**，不匹配绝不安装；检查与下载全在后台线程，不影响大厅渲染与游戏启动。**车机现实约束**：部分车机固件禁止拉起「未知来源」安装器或把开关藏在系统设置深处，此时应用自动把 APK 复制到 **Download 目录**并提示用文件管理器打开安装（覆盖安装，数据不丢）
- **车机性能：图片资源瘦身（卡顿主因）**：游戏封面原为 1664×2496 JPEG（约 1.2MB/张），车机屏上实际只显示约 316×475px——解码后 10 张封面就占约 166MB 位图，是「778G 也卡」的真正原因。全部改为 **720×1080 WebP**（12MB → 0.7MB），全部图片加 `decoding="async"` + 首屏图 `fetchPriority="high"`、非首屏 `loading="lazy"`；前端资源 89MB → 28MB，安装包 **69MB → 22.8MB**，画面观感不变
- **车机诊断面板（无需 root/ADB）**：设置页新增「车机诊断」，直接显示系统视角数据——音频焦点/媒体会话、**全部输出端口（车机多路为 BUS 通道）**、当前活跃播放被路由到哪、系统是否识别手柄、内存与 BYD 组件列表，并探测本机是否存在 BYD 专属音频通道接口；「导出诊断报告」写入剪贴板即可粘贴给开发者，用于定位「无声 / 进不了游戏模式 / 连手柄泛白」
- **车机无声修复（音频路由）**：依据真车诊断报告——焦点已授予、媒体会话已激活且存在活跃播放流，但车机把第三方媒体流默认路由到**不接喇叭的通道**（输出列表里并列着「听筒/通话」口）。本版做三件事：①注册 **MediaBrowserService** 让车机 CarAudioService 把应用识别为媒体源并分配扬声器 zone；②新增**音频输出路由**：常驻 MEDIA+CONTENT_TYPE_MUSIC 静音流并 `setPreferredDevice` 显式绑定通道，读取**实际路由设备**；③设置页「车机诊断」新增**音频输出通道选择器**，车机上无需 ADB 即可手动切通道（默认锚定内置扬声器）。另修正手柄枚举（改用公开 API，此前真车显示 0 个是隐藏 API 被拦）
- **车机通道测试音（无声问题决定性实验）**：设置页「车机诊断 → 音频输出通道」新增「播放通道测试音」，走与锚定流同一条 `USAGE_MEDIA + CONTENT_TYPE_MUSIC` 的 AudioTrack 播 1kHz/0.6s 真实音频（播完自动恢复静音）。**能听到 → 通道通、问题在 WebAudio 的 contentType（车机报告里活跃流是未声明类型）；听不到 → 该通道被车机音频策略丢弃**，两条路各修各的，不再靠猜
- **安装兼容性修正**：比亚迪车机安装器对含 `android.media.browse.MediaBrowserService` 的包报「解析软件包出现问题」——该组件（媒体源注册）只是推测性的一招，**先摘除**，音频路由锚定与通道测试音不依赖它，实验照常进行
- **车机音频全通道扫描（纠正通道语义）**：逆向 DiPlay 的实测方案得知——BYD 车机的「音频通道」不是输出设备，而是 **legacy stream type 1–20**（DiPlay 源码注释：0=usage 方式，1–20=车机支持的 legacy 通道；它优先用老式 `AudioTrack(streamType,…)` 构造器）。本版改为按通道号建流，设置页新增「音频通道扫描」：1→20 逐路播 0.35s 测试音，逐路给出**能否播放 / 实际路由设备 / 系统音量与静音**，每路可单独试听与绑定，默认锚定 STREAM_MUSIC(3)
- **车机音频二分诊断（A/B 对照 + 试验开关）**：真车实测「原生测试音每一路都能听到、但网页音乐全哑」→ 证明**车机路由是通的，问题在网页侧音频**；报告里活跃流的 `contentType: TYPE_0`（未声明内容类型）是嫌疑点。本版在诊断面板加：① **A · `<audio>` 测试音** 与 **B · WebAudio 测试音** 对照；② **「开启网页音频走媒体通道」开关**（WebAudio 经 MediaStream→`<audio>` 输出，以 `CONTENT_TYPE_MUSIC` 身份出声，模拟器实测该桥接可用）；③ 通道扫描新增 **usage + CONTENT_TYPE_UNKNOWN** 对照行
- **修测试音阻塞**：原生测试音此前缓冲区只有 16KB 却要塞 0.35s×44.1kHz×立体声≈61KB 数据，`write()` 会一直等硬件消费完而**阻塞调用线程**（车机上会卡界面）。现按音频长度给足缓冲区，音量降到 0.4（清晰可闻又不压满音频管线）
- **平台闭环（后台加游戏 → 车机可玩 → 后台看人数）**：客户端启动后异步拉取远程目录（3 秒超时静默降级，远程覆盖同 id 内置、未覆盖的内置全部保留，断网仍有内置 10 款）；远程游戏点「开始」直接在线直玩（走后台下发的绝对地址，无需下载）；埋点 `session_open/game_start/game_end` 上报，后台「统计」区显示每款游戏的今日人数（按设备去重）、次数、时长与近 7 日趋势。服务端托管 `/play/<id>/` 供在线直玩，并修了 `/api/catalog` 缺 CORS 头导致车机跨域拉目录被拦的问题
- **详情页一屏化**：游戏详情重做为横向三栏（海报｜信息｜预览），一屏显示完整、无需上下滚动；简介自适应行数、规格压成 chips、版本移顶栏、安装状态做海报徽标；1280×720 / 1024×600 / 1920×1080 三档分辨率实测均不溢出，保留三套主题与手柄导航
- **画面缩放锁定**：viewport 锁 `maximum-scale=1 / user-scalable=no` + WebView 关闭缩放支持/控件/overview 模式，页面恒 100% 贴合屏幕，修复车机「一会全屏一会放大」的缩放漂移

## 版本历史

- **V1.23**：大厅 60fps 第二轮 —— 定位到「没建合成层的卡每帧重绘」（Adreno 643 真 GPU 上瓶颈不是层数），位移改 `translate3d` + 视野内卡片全部提升为合成层，拖拽期不画倒影；修掉帧采样「不足 12 帧丢弃」导致真车永远拿不到数据；PCM 中转把 worklet 累积到 2048 帧再过桥（每秒 375 次 → 24 次）、原生按源采样率 48k 播放不再裸抽取降采样、写入线程提到 URGENT_AUDIO；移除走不通的「网页音频走媒体通道」开关；门禁 40/40
- **V1.22**：大厅滑动掉帧改用「设备上实测帧间隔 + 自动降档」根治（三档：完整/精简/平面，只减特效不改布局交互，门禁 25/25）；清理逐帧样式污染（遮罩量化、zIndex/pointerEvents 仅在变化时写、每帧内联写入 −64%）；合成层收紧到视野内卡片；背景横幅预解码消除切卡长帧；诊断报告新增 GPU 渲染器字符串 + 实测帧间隔 + 当前档位
- **V1.21**：修 PCM 中转的三处叠加缺陷（媒体通道与 PCM 双路同播导致卡顿、关闭后不可逆、主线程采集在游戏满载时丢回调），采集改 AudioWorklet、采样率随每个 context 走、焦点丢失 1.2s 后重申请
